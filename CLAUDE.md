# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`ai-api` is a pre-alpha (0.0.2), async-first, low-level toolkit for building typed HTTP API clients (aimed at AI providers such as OpenAI/Anthropic). It provides infrastructure only — no provider-specific calls exist yet. The public surface is unstable.

## Commands

The project is managed with `uv` (see `uv.lock`) and requires Python 3.15 (`.python-version`). Version is read by hatchling from `src/ai_api/__meta__.py`.

```bash
uv sync --all-groups                 # install runtime + dev + test deps
uv run ruff check src                # lint (line length 79)
uv run ruff format src               # format
uv run mypy src                      # strict type checking (pydantic.mypy plugin)
uv run pytest                        # tests (testpaths = tests, asyncio_mode = auto)
uv run pytest tests/path/test_x.py::test_name   # single test
uv run pytest --cov                  # with coverage (branch coverage on ai_api)
```

There is no `tests/` directory yet; the pytest config expects one at the repo root. Test tooling includes `aresponses` and `pytest-aiohttp` for mocking aiohttp servers.

## Architecture

Request flow: a `BaseAPIMethod` instance → `BaseSession.send_request` → (optional tenacity retry around) `BaseSession._send_once` → transport `_execute` → `BufferedResponse` → `_raise_for_status` → the method's `response_parser` → typed result.

Stream flow: a `BaseStreamMethod` instance → `async with BaseSession.stream(method)` → (retry around) `_open_stream_once` → transport `_open_stream` → `IStreamResponse` (body unread; ≥400 is read and raised here, still inside the retry) → `yield Stream(method.stream_parser.parse(...))` → on exit the parser generator and the response are closed (also on `break`/exceptions). Only opening is retried; failures while iterating reach the caller.

- **Methods (`methods/base.py`)** — Each API call is a Pydantic model subclassing `BaseAPIMethod[T]` (buffered; `T` is the whole parsed response) or `BaseStreamMethod[T]` (`T` is one streamed item). Both derive from `BaseMethod[T]`, which holds the shared request contract. Behavior is configured via dunder `ClassVar`s: `__request_path__`, `__request_method__`, `__request_query__` (set of field names sent as query params; everything that is neither a path nor a query param goes to the body), `__request_body_format__` (`BodyFormat`), `__returning__`, `__response_format__`, `__response_mode__`, `__retryable__`, plus `__response_parser__` / `__stream_parser__`. Fields are the request parameters; `get_query_map()` / `get_body_map()` split them. `__pydantic_init_subclass__` infers `__returning__` from the generic argument and, unless a non-library class in the MRO sets it (`_BASE_METHODS` are skipped), `__response_format__` via `_infer_response_format` (`str` → TEXT, `bytes` → BYTES, `None` → NONE; buffered also model → JSON; stream defaults to BYTES).
- **Path parameters** — `{field}` placeholders in `__request_path__` are parsed once in `_init_path_params` (run for every subclass, generic or not) into `__request_path_params__`; bad templates, missing fields and path/query overlap raise `TypeError` at class definition. `request_path` fills them per request with `quote(value, safe=__path_safe__)` and rejects `None`, empty and `.`/`..` segments — the escaping is what prevents path injection, so keep it. `request_path` is therefore already encoded, and `IAPI.build_url` must join it with `URL.joinpath(..., encoded=True)` — yarl's `/` operator double-encodes (`%2F` → `%252F`). Path fields are excluded from `get_body_map()`.
- **Method protocols (`methods/protocols.py`)** — `IBaseMethod[T]` (shared), `IAPIMethod[T]` (+ `response_parser`) and `IStreamMethod[T]` (+ `stream_parser`); the split makes `send_request(stream_method)` / `stream(buffered_method)` type errors. They expose only regular properties/methods (`request_path`, `body_format`, `retryable`, `response_format`, `response_type`, …), never the dunder `ClassVar`s; the base classes map the dunders onto these properties. Consumers (session, parser) must use the properties: putting dunder `ClassVar`s back into a protocol breaks protocol matching in pyright. `response_type: type[T] | None` is what lets `send_request`/`stream` infer `T`.
- **Session (`client/session/`)** — `BaseSession` holds all transport-agnostic logic: api/auth/error_resolver/headers/json codecs, the retry loop (4 attempts, only if `retryable`), turning ≥400 responses into `APIError` via the error resolver, and parsing. The status check must stay inside the retried `_send_once`, since retries are driven by the raised error's `transient` flag. A transport only implements `_execute(method) -> BufferedResponse`, `_open_stream(method) -> IStreamResponse` (both return error statuses and raise `APITransportError` subclasses for I/O failures) and `close()`. `AiohttpSession` builds the `ClientSession` lazily (certifi SSL context, User-Agent + Authorization headers, `timeout` defaulting to 600s total / 30s connect instead of aiohttp's 300s) and passes `stream_timeout` (no total limit, 600s `sock_read` between chunks) per stream request. `_transport_errors()` maps aiohttp exceptions in one place, including mid-stream in `_AiohttpStreamResponse.iter_chunks()`.
- **Body building (`client/session/builders/aiohttp.py` + `client/serialization/body.py`)** — `BodyNormalizer` converts values first (drops `None`, dumps nested `BaseAPIType`, unwraps enums, tz-aware datetimes → unix-timestamp strings, timedeltas → now+delta timestamps). `AiohttpBodyBuilder` then emits aiohttp kwargs (`json=` or `data=FormData`), rejecting binary/file data outside multipart.
- **Files (`types/files.py`)** — Uploads are `InputFile` objects (`BytesFile`, `PathFile`, `IOFile`, `StreamFile`), deliberately not `BaseAPIType` (the normalizer would `model_dump` them). They are transport-neutral: `open()` yields a fresh `AsyncIterator[bytes]` on every call, which is what makes retries resend full content; `reusable=False` (`StreamFile`, non-seekable `IOFile`) makes `BaseAPIMethod.retryable` false. A field typed `InputFile` coerces `bytes`/paths/binary streams via `__get_pydantic_core_schema__`; `BaseAPIMethod.model_post_init` also wraps raw binary streams in any field into `IOFile`, because pydantic's `model_dump()` would otherwise turn them into lazy `SerializationIterator`s. The aiohttp body builder maps them to multipart fields (`filename`, `content_type`). `PathFile` reads via `aiofiles` (typed through the `types-aiofiles` dev stub); `IOFile` wraps an already-open stream, so it reads via `asyncio.to_thread`.
- **Response parsing (`client/response/parse/`)** — `BufferedResponseParser` dispatches on `ResponseFormat` (JSON, TEXT, BYTES, NONE). `StreamResponseParser` returns an `AsyncIterator[T]` for BYTES (raw chunks) and TEXT (incremental decoding, so multi-byte characters split across chunks survive); `SSE`/`NDJSON` are declared in the enum but not implemented yet. `Stream[T]` (`client/response/stream.py`) is what callers iterate; `save(path)` is typed with `self: Stream[bytes]`, so it is only available on byte streams.
- **Errors** — Everything derives from `AIAPIError` (`exceptions.py`), which composes `default_message` + `"detail: <message>"`. HTTP errors (`client/exceptions/http.py`) are `APIError` subclasses keyed by status in `HTTP_ERRORS`; transport errors (`client/exceptions/transport.py`) are `APITransportError` subclasses. Both carry a `transient` flag, which is the sole retry criterion (`client/retry/startegy.py`); waits use random exponential jitter but honor `retry_after`.
- **Error resolver (`client/exceptions/errror_resolver/base.py`)** — `BaseErrorResolver.resolve()` extracts `{"error": {code,type,message}}`, request-id headers, and `Retry-After`, then `classify()` picks the error class and transience. Provider-specific behavior is meant to be added by subclassing and overriding `provider`, `get_error_code`, and `classify`.
- **Protocols** — Most components have an `I*` `Protocol` in a sibling `protocols.py` (`IAPI`, `IAuth`, `IHeaders`, `IErrorResolver`, `IAPIMethod`/`IStreamMethod`, `IResponseParser`/`IStreamParser`, `IStreamResponse`, `IBodyBuilder`, `ISession`). Sessions depend on protocols, not concrete classes; the user supplies an `IAPI` (base_url/version/`build_url`) per provider.

## Conventions

- Every module, class, function and method (including private ones and protocol members) has a Google-style docstring (`Args:`, `Returns:`, `Yields:`, `Raises:`, `Attributes:`, `Example:`). Ruff enforces this (`D` rules, `convention = "google"` in `pyproject.toml`), so `uv run ruff check src` fails on missing or malformed docstrings.- Uses modern syntax: PEP 695 generics (`class Foo[T]`, `def parse[T]`, `type X = ...`) and relies on deferred annotation evaluation (names imported under `TYPE_CHECKING` are used unquoted in annotations).
- Note the misspelled module paths `errror_resolver` and `retry/startegy.py` — they are the real import paths; don't "fix" them in imports without renaming the modules.
- Ruff rule set is broad (pylint, bugbear, simplify, etc.); `print` is disallowed (T20) and naive datetimes are flagged (DTZ).
