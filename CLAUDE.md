# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`ai-api` is a pre-alpha (0.0.2), async-first, low-level toolkit for building typed HTTP API clients (aimed at AI providers such as OpenAI/Anthropic). It provides infrastructure only — no provider-specific calls exist yet. The public surface is unstable.

## Commands

The project is managed with `uv` (see `uv.lock`) and requires Python 3.15 (`.python-version`). Version is read by hatchling from `src/ai_api/__meta__.py`.

```bash
uv sync --all-groups                 # install runtime + dev + test deps
uv run ruff check src tests          # lint (line length 79)
uv run ruff format src tests         # format
uv run mypy src                      # strict type checking (pydantic.mypy plugin)
uv run pyright                       # strict pyright over src and tests
uv run pytest                        # tests (testpaths = tests, asyncio_mode = auto)
uv run pytest tests/path/test_x.py::test_name   # single test
uv run pytest --cov                  # with coverage (branch, fail_under = 98)
uv run pytest --mypy -m mypy tests/typing       # static checks of the public API
uv run pre-commit install            # once: hooks from .pre-commit-config.yaml
```

Tests live in `tests/` (`unit/`, `session/`, `integration/`, `typing/`, `docs/`); shared doubles and fixtures are in `tests/conftest.py`, and the plan is `docs/testing-plan.md`. `tests/typing/check_public_api.py` is never run: every `# type: ignore[...]` there marks a line that must stay a type error. `tests/docs/test_readme.py` runs every ```` ```python ```` block of `README.md`, so a new README example needs a test. CI (`.github/workflows/tests.yml`) runs the same commands; pytest on Ubuntu and Windows.

## Architecture

Request flow: a `BaseAPIMethod` instance → `BaseSession.send_request` → (optional tenacity retry around) `BaseSession._send_once` → transport `_execute` → `BufferedResponse` → `_raise_for_status` → the method's `response_parser` → typed result.

Stream flow: a `BaseStreamMethod` instance → `async with BaseSession.stream(method)` → (retry around) `_open_stream_once` → transport `_open_stream` → `IStreamResponse` (body unread; ≥400 is read and raised here, still inside the retry) → `yield Stream(method.stream_parser.parse(...))` → on exit the parser generator and the response are closed (also on `break`/exceptions). Only opening is retried; failures while iterating reach the caller.

- **Methods (`methods/base.py`)** — Each API call is a Pydantic model subclassing `BaseAPIMethod[T]` (buffered; `T` is the whole parsed response) or `BaseStreamMethod[T]` (`T` is one streamed item). Both derive from `BaseMethod[T]`, which holds the shared request contract. Behavior is configured via dunder `ClassVar`s: `__request_path__`, `__request_method__`, `__request_query__` (set of field names sent as query params; everything that is neither a path nor a query param goes to the body; `_init_query_params` rejects unknown names and mapping/model-typed fields at class definition, and `get_query_map()` returns the `Query` alias from `client/api/protocols.py`, where a list value is a repeated key), `__request_body_format__` (`BodyFormat`), `__returning__`, `__response_format__`, `__response_mode__`, `__retryable__`, plus `__response_parser__` / `__stream_parser__`. Fields are the request parameters (`extra="forbid"`, so typos fail validation; `validate_by_name` + `validate_by_alias`, and wire names go in `validation_alias`/`serialization_alias`, not `alias`, so mypy and pyright both take the field name in the constructor); `get_query_map()` / `get_body_map()` split them. `__pydantic_init_subclass__` infers `__returning__` from the generic argument and `__response_format__` via `_infer_response_format` (`str` → TEXT, `bytes` → BYTES, `None` → NONE; buffered also model → JSON; stream knows `bytes`/`str`/`ServerSentEvent` (→ SSE) and defaults to BYTES); each is kept when a non-library class in the MRO sets it explicitly (`_defines`; `_BASE_METHODS` are skipped). After inference, `_validate_response_type()` runs on user-declared classes only (`__pydantic_generic_metadata__["origin"] is None`): a parametrized class like `BaseStreamMethod[Event]` exists before the subclass body that may set the format, so validating it would make explicit overrides impossible. `BaseStreamMethod` rejects other item types (including unions and non-class arguments such as `list[int]`) unless `__response_format__` or `__stream_parser__` is set explicitly, and for SSE/NDJSON builds `__response_adapter__` there (`TypeError` if Pydantic cannot build it).
- **Path parameters** — `{field}` placeholders in `__request_path__` are parsed once in `_init_path_params` (run for every subclass, generic or not) into `__request_path_params__`; bad templates, missing fields and path/query overlap raise `TypeError` at class definition. `request_path` fills them per request with `quote(value, safe=__path_safe__)` and rejects `None` (and values such as NaN that dump to `null`), empty and `.`/`..` segments — the escaping is what prevents path injection, so keep it. `request_path` is therefore already encoded, and `IAPI.build_url` must join it with `URL.joinpath(..., encoded=True)` — yarl's `/` operator double-encodes (`%2F` → `%252F`). Path fields are excluded from `get_body_map()`.
- **Method protocols (`methods/protocols.py`)** — `IBaseMethod[T]` (shared), `IAPIMethod[T]` (+ `response_parser`) and `IStreamMethod[T]` (+ `stream_parser`); the split makes `send_request(stream_method)` / `stream(buffered_method)` type errors. They expose only regular properties/methods (`request_path`, `body_format`, `retryable`, `response_format`, `response_type`, …), never the dunder `ClassVar`s; the base classes map the dunders onto these properties. Consumers (session, parser) must use the properties: putting dunder `ClassVar`s back into a protocol breaks protocol matching in pyright. `response_type: type[T] | None` is what lets `send_request`/`stream` infer `T`.
- **Session (`client/session/`)** — `BaseSession` holds all transport-agnostic logic: api/auth/error_resolver/headers/json codecs, the retry loop (4 attempts, only if `retryable`; `max_retry_after`, 60s by default, stops retrying an error whose `Retry-After` is longer; `retry_deadline`, 900s by default, adds `stop_before_delay` so no wait that would end after it starts), turning ≥400 responses into `APIError` via the error resolver, and parsing. The status check must stay inside the retried `_send_once`, since retries are driven by the raised error's `transient` flag. A transport only implements `_execute(method) -> BufferedResponse`, `_open_stream(method) -> IStreamResponse` (both return error statuses and raise `APITransportError` subclasses for I/O failures) and `close()`. `AiohttpSession` is bound to one event loop, the running loop in `__init__` or an explicit `loop=` (so it must be created inside a coroutine); `_check_loop()` in `create_session`/`close` raises `RuntimeError` from any other loop instead of aiohttp's unclear errors. It builds the `ClientSession` lazily, passing it that `loop` (certifi SSL context, User-Agent header, `trust_env` off by default, `timeout` defaulting to 600s total / 30s connect instead of aiohttp's 300s) and passes `stream_timeout` (no total limit, 600s `sock_read` between chunks) per stream request. The auth header (`{auth.header_name: auth.encode()}`; `BearerAuth` → `Authorization`, `APIKeyAuth` → `x-api-key` by default) is passed per request, so a rotating `IAuth` works. Redirects are off by default (`allow_redirects=False`); `follow_redirects=True` passes a per-request `_same_origin` aiohttp middleware that raises `APIRedirectError` before a hop to another origin is sent (aiohttp itself strips only `Authorization`, so `x-api-key`/default headers would leak). Any 3xx that reaches `_request` (not followed, or without `Location`) becomes `APIRedirectError`, and a `ClientPayloadError` while sending (a 307/308 needing a consumed upload body) becomes `APIRequestError`. `max_body_size` (off by default) limits buffered and error bodies via `_read_body`. The URL and body are built before `_transport_errors()`, so builder errors stay raw; inside it, aiohttp exceptions are mapped in one place (also mid-stream in `_AiohttpStreamResponse.iter_chunks()`): `TooManyRedirects` → `APIRedirectError`, a connection error caused by a failing upload source → that source's `APIRequestError` (found in the cause chain), other `ClientResponseError` → `APIResponseError`, and `ValueError` last (invalid header or URL; certificate errors are `ValueError`s too, hence the order) → `APIRequestError`.
- **Body building (`client/session/builders/aiohttp.py` + `client/serialization/body.py`)** — `BodyNormalizer` converts values first (drops `None` fields of the body and of nested models but keeps `None` inside lists/dicts, dumps nested `BaseAPIType`, unwraps enums, tz-aware datetimes → unix-timestamp strings, timedeltas → now+delta timestamps, `ValueError` on circular references and on nesting deeper than `MAX_DEPTH` = 256, before Python's recursion limit). `AiohttpBodyBuilder` then emits `data=` with JSON already encoded by `json_dumps` into a `BytesPayload` (a `str` result, e.g. from `json.dumps`, is UTF-8 encoded; encoder errors become a clear `TypeError`; NaN/infinity are rejected first, since orjson writes them as `null`) or a `FormData`, rejecting binary/file data outside multipart. Uploads are checked with `InputFile.check()` (a missing `PathFile` or a directory → `APIRequestError`) and read through `_read_source`, which turns source failures into `APIRequestError` so they are not retried as connection errors.
- **Files (`types/files.py`)** — Uploads are `InputFile` objects (`BytesFile`, `PathFile`, `IOFile`, `StreamFile`), deliberately not `BaseAPIType` (the normalizer would `model_dump` them). They are transport-neutral: `open()` yields a fresh `AsyncIterator[bytes]` on every call, which is what makes retries resend full content; `reusable=False` (`StreamFile`, non-seekable `IOFile`) makes `BaseAPIMethod.retryable` false. A field typed `InputFile` coerces `bytes`/paths/binary streams via `__get_pydantic_core_schema__`; `BaseAPIMethod.model_post_init` also wraps raw binary streams in any field into `IOFile`, because pydantic's `model_dump()` would otherwise turn them into lazy `SerializationIterator`s. The aiohttp body builder maps them to multipart fields (`filename`, `content_type`); `check()` is a pre-send hook (only `PathFile` overrides it). `PathFile` reads via `aiofiles` (typed through the `types-aiofiles` dev stub); `IOFile` wraps an already-open stream, so it reads via `asyncio.to_thread`.
- **Response parsing (`client/response/parse/`)** — `BufferedResponseParser` dispatches on `ResponseFormat` (JSON, TEXT, BYTES, NONE); JSON uses `model_validate_json` with the default decoder (JSON-mode semantics for strict fields) and `model_validate(json_loads(raw))` only for a custom decoder. `StreamResponseParser` returns an `AsyncIterator[T]` for BYTES (raw chunks), TEXT (incremental decoding, so multi-byte characters split across chunks survive; the server-chosen charset must be a text codec, checked via `codecs.lookup(...)._is_text_encoding`, because the incremental decoder also accepts base64/zlib/rot13), SSE and NDJSON. For the last two, `LineDecoder` (`parse/lines.py`) splits UTF-8 into lines on `\n`/`\r\n`/`\r` across chunk boundaries (optional `max_line_size`, set via `StreamResponseParser(max_line_size=...)`), `SSEDecoder` (`parse/sse.py`) assembles events per the HTML standard (optional `max_event_size` on the joined `data`), SSE requires `Content-Type: text/event-stream` unless `StreamResponseParser(require_event_stream=False)` (an HTML 200 from a proxy would otherwise be a silently empty stream), and each event is validated through `method.response_adapter` (a `TypeAdapter` built at class definition from `__stream_item__`, the generic argument as written, so discriminated unions and `type` aliases work; `None` for `ServerSentEvent` items, which are yielded raw). `data: [DONE]` ends a stream; an SSE `error` event, or data that the overridable `StreamResponseParser.is_error_event` accepts (`type == "error"`, or no `type` and a top-level `error` that is `true` or a non-empty object/string; `null`/`false`/empty mean no error, as in OpenAI batch lines; an event with another `type` may carry an `error` field as data), goes through the session's error resolver (passed to `IStreamParser.parse` like `json_loads`), with the stream's own status. Stream item types other than `bytes`/`str`/`ServerSentEvent` need an explicit `__response_format__` or `__stream_parser__`. `Stream[T]` (`client/response/stream.py`) is what callers iterate; it is its own async iterator and checks for `aclose()` in `__anext__`, so iterating it outside the `async with`, even via an `aiter()` taken inside, raises `RuntimeError`; `save(path)` is typed with `self: Stream[bytes]`, so it is only available on byte streams.
- **Errors** — Everything derives from `AIAPIError` (`exceptions.py`), which composes `default_message` + `"detail: <message>"` and pickles/copies through `__reduce__` (rebuilt from `args` + `__dict__`, never re-running `__init__`). HTTP errors (`client/exceptions/http.py`) are `APIError` subclasses keyed by status in `HTTP_ERRORS`; transport errors (`client/exceptions/transport.py`) are `APITransportError` subclasses (`APIRedirectError`, for a redirect that is not followed, and `APIRequestError` are non-transient). Both carry a `transient` flag, which is the sole retry criterion (`client/retry/startegy.py`); waits use random exponential jitter but honor `retry_after`.
- **Error resolver (`client/exceptions/errror_resolver/base.py`)** — `BaseErrorResolver.resolve()` extracts `{"error": {code,type,message}}` (a string `error` becomes the message), request-id headers, and `Retry-After`, then `classify()` picks the error class and transience (429 is transient only with `Retry-After`). Provider-specific behavior is meant to be added by subclassing and overriding `provider`, `get_error_code`, and `classify`.
- **API (`client/api/base.py`)** — `BaseAPI` validates `base_url` (absolute HTTP(S), no query/fragment) and `version` (one segment of unreserved characters, not `.`/`..`), because both are joined with `encoded=True`.
- **Protocols** — Most components have an `I*` `Protocol` in a sibling `protocols.py` (`IAPI`, `IAuth`, `IHeaders`, `IErrorResolver`, `IAPIMethod`/`IStreamMethod`, `IResponseParser`/`IStreamParser`, `IStreamResponse`, `IBodyBuilder`, `ISession`). Sessions depend on protocols, not concrete classes; the user supplies an `IAPI` (base_url/version/`build_url`) per provider.

## Conventions

- Every module, class, function and method (including private ones and protocol members) has a Google-style docstring (`Args:`, `Returns:`, `Yields:`, `Raises:`, `Attributes:`, `Example:`). Ruff enforces this (`D` rules, `convention = "google"` in `pyproject.toml`), so `uv run ruff check src` fails on missing or malformed docstrings.- Uses modern syntax: PEP 695 generics (`class Foo[T]`, `def parse[T]`, `type X = ...`) and relies on deferred annotation evaluation (names imported under `TYPE_CHECKING` are used unquoted in annotations).
- Note the misspelled module paths `errror_resolver` and `retry/startegy.py` — they are the real import paths; don't "fix" them in imports without renaming the modules.
- Ruff rule set is broad (pylint, bugbear, simplify, etc.); `print` is disallowed (T20) and naive datetimes are flagged (DTZ).
