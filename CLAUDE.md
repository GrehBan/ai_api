# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`ai-api` is a pre-alpha (0.2.0), async-first, low-level toolkit for building typed HTTP API clients (aimed at AI providers such as OpenAI/Anthropic). It provides the infrastructure plus a first provider client (`OpenAIClient`) with the methods and types of OpenAI's Responses API and the shared `client.generation` resource, and an `AnthropicClient` with the methods and types of Anthropic's Messages API; both have the shared `client.generation` resource. The public surface is unstable.

## Commands

The project is managed with `uv` (see `uv.lock`) and requires Python 3.13 or newer (`.python-version` pins 3.13, the oldest supported version, so local runs and CI catch newer syntax). Version is read by hatchling from `src/ai_api/__meta__.py`.

```bash
uv sync --all-groups                 # install runtime + dev + test deps
uv run ruff check src tests          # lint (line length 79)
uv run ruff format src tests         # format
uv run mypy src                      # strict type checking (pydantic.mypy plugin)
uv run pyright                       # strict pyright over src and tests
uv run pytest                        # tests (testpaths = tests, asyncio_mode = auto)
uv run pytest tests/path/test_x.py::test_name   # single test
uv run pytest --cov                  # with coverage (branch, fail_under = 98)
uv run pytest --mypy -m mypy tests/typing       # static checks of the public API
uv run pre-commit install            # once: hooks from .pre-commit-config.yaml
```

Tests live in `tests/` (`unit/`, `session/`, `integration/`, `providers/`, `typing/`, `docs/`; `providers/test_generation_contract.py` runs the same scenarios against every provider's `client.generation`, so a new provider adds a `Case` there, and `providers/test_provider_clients.py` does the same for the client itself (token, environment, warnings about a given session), with a `ClientCase`; `providers/test_<name>_client.py` keeps only what is the provider's own (its error resolver); `providers/test_wire_contracts.py` checks every provider endpoint against the upstream JSON schemas and documentation examples snapshotted in `tests/providers/contracts/`, whose request schemas it closes so unknown fields fail: a new endpoint adds an `Endpoint` to `contracts/update.py` and a `Case`, and `uv run python -m tests.providers.contracts.update [DOCS_LITE_DIR]` refreshes the snapshot from the docs dump, listing rejected examples in `manifest.json`; it also requires `__upstream_schema__`, a `BaseAPIType` `ClassVar` naming the upstream `$def` a model mirrors (several names, or `()` for none), on every provider model except the `BaseUnknown` ones, and checks each field against it: present upstream, nullable and optional where upstream is); `providers/test_stream_splits.py` sends every two-chunk split of the documented streams through `generation.stream`; `unit/test_decoder_properties.py` holds the hypothesis property tests of the decoders; `integration/test_close_delimited.py` cuts a close-delimited body with a raw socket server; shared doubles and fixtures are in `tests/conftest.py` (`Recorder`, the local server, answers only what a test scripted with `recorder.reply(...)` or an explicit `recorder.default`; any other request gets a 500 and fails the test at teardown, so a hidden retry or an extra request cannot pass; `no_close_delay` patches only `session.aiohttp._CLOSE_DELAY` and `frozen_now` only `http.headers._now`, the library's one clock read); ## Architecture

Request flow: a `BaseAPIMethod` instance → `BaseSession.send_request` → (optional tenacity retry around) `BaseSession._send_once` → transport `_execute` → `BufferedResponse` → `_raise_for_status` → the method's `response_parser` → typed result.

Stream flow: a `BaseStreamMethod` instance → `async with BaseSession.stream(method)` → (retry around) `_open_stream_once` → transport `_open_stream` → `IStreamResponse` (body unread; ≥400 is read and raised here, still inside the retry) → `yield Stream(method.stream_parser.parse(...))` → on exit the parser generator and the response are closed (also on `break`/exceptions). Only opening is retried; failures while iterating reach the caller, a transport error as `APIStreamInterruptedError`. With a declared `__stream_terminal__`, the parser also checks the end: no terminal → `APIStreamInterruptedError`, an item after it → `APIResponseError`.

- **Methods (`methods/base.py`)** — Each API call is a Pydantic model subclassing `BaseAPIMethod[T]` (buffered; `T` is the whole parsed response) or `BaseStreamMethod[T]` (`T` is one streamed item).
  - Both derive from `BaseMethod[T]`, which holds the shared request contract.
  - Behavior is configured via dunder `ClassVar`s: `__request_path__`, `__request_method__`, `__request_query__` (set of field names sent as query params, stored as a `frozenset` by `_init_query_params`, empty by default; everything that is neither a path nor a query param goes to the body; `_init_query_params` rejects unknown names and mapping/model-typed fields at class definition (`_init_path_params` rejects container-typed path fields, `is_container_type`, and `encode_path_value` an object or list value), and `get_query_map()` returns the `Query` alias from `http/protocols.py`, where a list, tuple or set value is a repeated key and `None` in it raises `ValueError`; query and path values are dumped in Python mode and written by `scalar_text` (`serialization/values.py`, the one rule for query, path and form scalars: enum → value, bool → `true`/`false`, dates through the formatter, NaN/infinity → `ValueError`, other types as pydantic writes them in JSON, `TypeError` for a value with no text form)), `__request_body_format__` (`BodyFormat`), `__value_formatter__` (an `IValueFormatter` from `serialization/protocols.py`, `BaseValueFormatter()` from `serialization/values.py` by default: ISO 8601, naive datetime → `ValueError`; property `value_formatter`, also on `IBaseMethod`; a provider sets its own on its base method, one field uses pydantic `PlainSerializer`, which runs before it; body, form, query and path all go through it), `__request_headers__` (`HeadersType | None`; `request_headers` returns a new `Headers` on every access, so callers may mutate it), `__returning__`, `__response_format__`, `__retryable__`, plus `__response_parser__` / `__stream_parser__`, and on streams `__stream_terminal__` (an `IEventMatcher` naming the protocol's last event, `None` by default; property `stream_terminal`, also on `IStreamMethod`).
  - Fields are the request parameters (`extra="forbid"`, so typos fail validation; `validate_by_name` + `validate_by_alias`, and wire names go in `validation_alias`/`serialization_alias`, not `alias`, so mypy and pyright both take the field name in the constructor); `get_query_map()` / `get_body_map()` split them.
  - `_check_body_fields` (run after `_init_path_params`) raises `TypeError` for a class with a `__request_path__` and `BodyFormat.NONE` whose field (other than `exclude=True` ones) is neither a path nor a query parameter, since it would never be sent; the aiohttp body builder refuses a non-empty body for `NONE` too.
  - `__pydantic_init_subclass__` infers `__returning__` from the generic argument and `__response_format__` via `_infer_response_format` (`str` → TEXT, `bytes` → BYTES, `None` → NONE; buffered also model → JSON; stream knows `bytes`/`str`/`ServerSentEvent` (→ SSE) and defaults to BYTES); each is kept when a non-library class in the MRO sets it explicitly (`_defines`; `_BASE_METHODS` are skipped).
  - After inference, `_validate_response_type()` runs on user-declared classes only (`__pydantic_generic_metadata__["origin"] is None`): a parametrized class like `BaseStreamMethod[Event]` exists before the subclass body that may set the format, so validating it would make explicit overrides impossible.
  - `BaseStreamMethod` rejects other item types (including unions and non-class arguments such as `list[int]`) unless `__response_format__` or `__stream_parser__` is set explicitly, and `_init_response_adapter()`, run right after it, builds `__response_adapter__` for SSE/NDJSON (`TypeError` if Pydantic cannot build it).
  - The same step checks that the format produces the declared type, because the parser's `cast`s would otherwise let a contradicting explicit format lie silently: buffered (once `__returning__` is known) TEXT → `str`, BYTES → `bytes`, NONE → `None`, JSON → a model, SSE/NDJSON rejected; stream BYTES → `bytes`, TEXT → `str` items, JSON/NONE rejected, SSE/NDJSON take any item.
  - A buffered generic argument that is not a class (`list[M]`, a union; kept as `__response_argument__`) raises `TypeError` the same way, and so does `__stream_terminal__` on a BYTES/TEXT stream (only SSE/NDJSON check it).
  - An explicit `__response_parser__` / `__stream_parser__` skips this check (tests use that to reach the parsers' own guards).
- **Method helpers** — `methods/base.py` keeps the class machinery; field-level helpers live in `methods/fields.py` (`is_mapping_type`, `query_value`, `resolve_response_type`, `wrap_streams`, `has_one_shot_file`) and path-template helpers in `methods/path.py` (`parse_path_params`, `encode_path_value`).
- **Path parameters** — `{field}` placeholders in `__request_path__` are parsed once in `_init_path_params` (run for every subclass, generic or not) into `__request_path_params__`; bad templates, missing fields and path/query overlap raise `TypeError` at class definition.
  - `request_path` always runs the template through `format_map`, so `{{`/`}}` are literal braces with or without placeholders, and fills them per request with `quote(value, safe=__request_path_safe__)` and rejects `None`, NaN/infinity (`scalar_text`), empty and `.`/`..` segments — the escaping is what prevents path injection, so keep it.
  - `request_path` is therefore already encoded, and `IAPI.build_url` must join it with `URL.joinpath(..., encoded=True)` — yarl's `/` operator double-encodes (`%2F` → `%252F`).
  - Path fields are excluded from `get_body_map()`.
- **Method protocols (`methods/protocols.py`)** — `IBaseMethod[T]` (shared), `IAPIMethod[T]` (+ `response_parser`) and `IStreamMethod[T]` (+ `stream_parser`); the split makes `send_request(stream_method)` / `stream(buffered_method)` type errors.
  - They expose only regular properties/methods (`request_path`, `body_format`, `retryable`, `response_format`, `response_type`, …), never the dunder `ClassVar`s; the base classes map the dunders onto these properties.
  - Consumers (session, parser) must use the properties: putting dunder `ClassVar`s back into a protocol breaks protocol matching in pyright.
  - `response_type: type[T] | None` is what lets `send_request`/`stream` infer `T`.
- **Session (`session/`)** — `BaseSession` holds all transport-agnostic logic: api/auth/error_resolver/headers/json codecs, the retry loop (`RETRY_ATTEMPT_LIMIT` = 4 attempts in `session/retry.py`, only if `retryable`; `max_retry_after`, 60s by default, stops retrying an error whose `Retry-After` is longer; `retry_deadline`, 900s by default, adds `stop_before_delay` so no wait that would end after it starts), turning ≥400 responses into `APIStatusError` via the error resolver, and parsing.
  - The status check must stay inside the retried `_send_once`, since retries are driven by the raised error's `transient` flag.
  - A transport only implements `_execute(method, *, headers=None, timeout=None) -> BufferedResponse`, `_open_stream(method, *, headers=None, timeout=None) -> IStreamResponse` (both return error statuses and raise `APITransportError` subclasses for I/O failures) and `close()`.
  - `send_request`/`stream` (also on `BaseClient`/`IClient`) take keyword-only per-call `headers: HeadersType | None` and `timeout: Timeout | None` (`type Timeout = float` seconds, `session/protocols.py`) and pass them to every attempt.
  - Headers are merged session < method `request_headers` < call `headers` < auth (`AiohttpSession._request` builds them for every request: `session.headers.build({User-Agent})`, updated by `method.request_headers.build(headers)`, then the auth header set last, so a call cannot replace it; the `ClientSession` holds no headers, so later `session.headers.add(...)` takes effect).
  - In `AiohttpSession`, `_replace_timeout` keeps every other limit: a call `timeout` replaces `total` of `timeout` for buffered requests and `sock_read` of `stream_timeout` for streams; `None` passes the session's `ClientTimeout` as is.
  - Never pass `timeout=None` to aiohttp: that disables every limit.
  - `BaseSession(headers=...)` keeps a given `IHeaders` (`runtime_checkable`) and copies a mapping into `Headers`.
  - `AiohttpSession` is bound to one event loop: an explicit `loop=`, or else the loop of its first use (so it can be created outside a coroutine, e.g. by `OpenAIClient(token)`); `self._loop = bind_loop(self._loop, owner)` (`session/loop.py`, transport-agnostic so another transport can reuse it) runs at the start of `get_client`/`close`, before the connector is built, and raises `RuntimeError` from any other loop instead of aiohttp's unclear errors.
  - The `loop` property is passive (`AbstractEventLoop | None`): reading it must never bind a loop.
  - It builds the `ClientSession` lazily, passing it that `loop` (certifi SSL context, `trust_env` off by default, `timeout` defaulting to 600s total / 30s connect instead of aiohttp's 300s) and passes `stream_timeout` (no total limit, 600s `sock_read` between chunks) per stream request.
  - The auth header (`{auth.header_name: auth.encode()}`; `BearerAuth` → `Authorization`, `APIKeyAuth` → `X_API_KEY` by default) is passed per request, so a rotating `IAuth` works.
  - Redirects are off by default (`allow_redirects=False`); `follow_redirects=True` passes a per-request `_same_origin` aiohttp middleware that raises `APIRedirectError` before a hop to another origin is sent (aiohttp itself strips only `Authorization`, so `x-api-key`/default headers would leak).
  - Any 3xx that reaches `_request` (not followed, or without `Location`) becomes `APIRedirectError`, and a `ClientPayloadError` while sending (a 307/308 needing a consumed upload body) becomes `APIRequestError`.
  - `max_body_size` (off by default) limits buffered and error bodies via `read_body(response, max_size)` (`response/aiohttp.py`, next to `AiohttpStreamResponse`).
  - The URL and body are built before `transport_errors()` (`http/exceptions/aiohttp.py`), so builder errors stay raw; inside it, aiohttp exceptions are mapped in one place (reading a body goes through `body_errors()`, which wraps it and maps a `ClientPayloadError`, a body cut off by a lost connection, to the transient `APIConnectionError`; so a buffered request or a stream's error body is retried and a stream cut mid-way fails as a transport error): `ClientConnectorCertificateError`/`ServerFingerprintMismatch` → non-transient `APITLSError` (any other SSL error, a broken-off handshake, is a transient `APIConnectionError`, as in the SDKs), `TooManyRedirects` → `APIRedirectError`, a connection error caused by a failing upload source → that source's `APIRequestError` (found in the cause chain), other `ClientResponseError` → `APIResponseError`, and `ValueError` last (invalid header or URL; certificate errors are `ValueError`s too, hence the order) → `APIRequestError`.
- **Body building (`session/body/aiohttp.py` + `serialization/normalize.py`)** — `BodyNormalizer` converts values first, with the method's formatter passed to `IBodyBuilder.build(body, body_format, formatter)` by the session (drops `None` fields of the body and of nested models but keeps `None` inside lists/dicts, dumps nested `BaseAPIType` by alias, unwraps enums, also as dict keys (two keys giving the same value → `ValueError`), writes dates, times and durations through the formatter, `TypeError` for a text stream, `ValueError` on circular references and on nesting deeper than `MAX_DEPTH` = 253, orjson's limit for a body field).
  - `AiohttpBodyBuilder` then emits `data=` with JSON already encoded by `json_dumps` into a `BytesPayload` (a `str` result, e.g. from `json.dumps`, is UTF-8 encoded; encoder errors become a clear `TypeError`; NaN/infinity are rejected first, since orjson writes them as `null`) or a `FormData` (scalars through `scalar_text`), rejecting binary/file data outside multipart, and `None` or a nested list inside a form list.
  - Uploads are checked with `InputFile.check()` (a missing `PathFile` or a directory → `APIRequestError`) and read through `_read_source`, which turns source failures into `APIRequestError` so they are not retried as connection errors.
- **Files (`types/files.py`)** — Uploads are `InputFile` objects (`BytesFile`, `PathFile`, `IOFile`, `StreamFile`), deliberately not `BaseAPIType` (the normalizer would `model_dump` them).
  - They are transport-neutral: `open()` yields a fresh `AsyncIterator[bytes]` on every call, which is what makes retries resend full content; `reusable=False` (`StreamFile`, non-seekable `IOFile`) makes `BaseAPIMethod.retryable` false.
  - A field typed `InputFile` coerces `bytes`/paths/binary streams via `__get_pydantic_core_schema__`; `BaseAPIMethod.model_post_init` also wraps raw binary streams in any field into `IOFile` (lists, tuples, dicts and nested models, by the one traversal `_children` that `has_one_shot_file` uses too; a nested model is copied, never changed in place, and a stream in a container it cannot rebuild, such as a dict subclass, raises `TypeError`), because pydantic's `model_dump()` would otherwise turn them into lazy `SerializationIterator`s.
  - The aiohttp body builder maps them to multipart fields (`filename`, `content_type`); `check()` is a pre-send hook (only `PathFile` overrides it).
  - `PathFile` reads via `aiofiles` (typed through the `types-aiofiles` dev stub); `IOFile` wraps an already-open stream, so it reads via `asyncio.to_thread`, and a non-blocking stream whose `read()` returns `None` raises `BlockingIOError` instead of ending the upload.
- **Matchers (`types/matchers.py`, protocol `IEventMatcher` in `types/protocols.py`)** — `matches(item: object) -> bool` on a model or decoded JSON alike: `EventTypes(*types)` (a `type`), `FieldValues(name, *values)` (any field: a mapping key, a model's field or extra field, never a property, which may raise, or another object's attribute; values compared as JSON tells them apart, `true` ≠ `1`, through `_key`; unhashable values never match; `EventTypes(*types)` is `FieldValues("type", ...)` with a `types` property, and the two compare equal by field and values), `TopLevelError()`, `DONE` (matches `DONE_MARKER`, the `[DONE]` line of the common SSE convention; neither provider uses it) and `AnyOf`, built with `|` (`BaseMatcher.__ror__` also lets a protocol-only matcher stand on the left).
  - They compare by value and their `repr` shows what they match (one matcher in an `AnyOf` shows as `AnyOf(x)`, since it is not equal to `x`).
  - Methods and parsers use them for terminals, error events and failed results.
- **Response parsing (`response/parse/`)** — `BufferedResponseParser(error_responses=...)` dispatches on `ResponseFormat` (JSON, TEXT, BYTES, NONE; a JSON result that the optional `error_responses` matcher accepts is raised through the error resolver, passed to `IResponseParser.parse` after `json_loads`, with the result in `raw`); JSON uses `model_validate_json` with the default decoder (JSON-mode semantics for strict fields) and `model_validate(json_loads(raw))` only for a custom decoder.
  - Parsers raise `APIResponseError` themselves for a body they cannot decode or validate ("Failed to decode …" for invalid JSON, "Failed to validate …" for a model mismatch, buffered and streamed alike), and the session does not wrap parser errors, so anything else surfaces as the bug it is.
  - `StreamResponseParser` returns an `AsyncIterator[T]` for BYTES (raw chunks), TEXT (incremental decoding, so multi-byte characters split across chunks survive; the server-chosen charset must be a text codec, checked via `codecs.lookup(...)._is_text_encoding` by `_text_decoder` in `parse()`, when the stream opens, because the incremental decoder also accepts base64/zlib/rot13), SSE and NDJSON.
  - For the last two, `LineDecoder` (`parse/lines.py`) splits UTF-8 into lines on `\n`/`\r\n`/`\r` across chunk boundaries (optional `max_line_size`, set via `StreamResponseParser(max_line_size=...)`), `SSEDecoder` (`parse/sse.py`) assembles events per the HTML standard (optional `max_event_size` on the joined `data`), a `ServerSentEvent` item whose data is JSON goes through `error_events` too (data that is not JSON is yielded as it is), the decoder keeps the last `retry` as it keeps the last `id` (the HTML standard applies both at once), SSE requires `Content-Type: text/event-stream` unless `StreamResponseParser(require_event_stream=False)` (an HTML 200 from a proxy would otherwise be a silently empty stream), and each event is validated through `method.response_adapter` (a `TypeAdapter` built at class definition from `__stream_item__`, the generic argument as written, so discriminated unions and `type` aliases work; `None` for `ServerSentEvent` items, which are yielded raw).
  - Every event is decoded with `json_loads` first (so the matchers see the same JSON the resolver gets), then validated (`validate_json` with the default decoder, `validate_python` with a custom one).
  - An SSE `error` event, or decoded data that the parser's `error_events` matcher accepts (`StreamResponseParser(error_events=...)`, default `ERROR_EVENTS` = `EventTypes("error") | TopLevelError()`: `type == "error"`, or no `type` and a top-level `error` that is `true` or a non-empty object/string; `null`/`false`/empty mean no error, as in OpenAI batch lines; an event with another `type` may carry an `error` field as data), goes through the session's error resolver, with the validated event in the error's `raw` when it fits the item type (passed to `IStreamParser.parse` together with `json_loads`; both are required arguments, parsers keep no defaults of their own), with the stream's own status; the error check runs before the terminal check.
  - The terminal (`_Ending` in `parse/stream.py`): without one, `data: [DONE]` ends the stream and nothing is checked; with one, `[DONE]` is matched as `DONE_MARKER` and never yielded, the body is read to EOF, an item after the terminal raises `APIResponseError` and EOF without it raises `APIStreamInterruptedError` (no cause); an early `break`/`aclose()` is never checked.
  - By HTTP/1.1 (RFC 9112 §6.3) and the SSE standard the end of a close-delimited body is a normal end, so only the terminal can tell a cut from the end.
  - Stream item types other than `bytes`/`str`/`ServerSentEvent` need an explicit `__response_format__` or `__stream_parser__`.
  - `Stream[T]` (`response/stream.py`) is what callers iterate; it wraps every `APITransportError` raised while iterating in `APIStreamInterruptedError` (with `items_received` and the original as `__cause__`; nested streams pass it through); it counts what it gave in the public `items_received`; it is its own async iterator and checks for `aclose()` in `__anext__`, so iterating it outside the `async with`, even via an `aiter()` taken inside, raises `RuntimeError`; `save(path)` is typed with `self: Stream[bytes]`, so it is only available on byte streams.
- **Errors** — Everything derives from `AIAPIError` (the root `ai_api/exceptions.py`, kept apart from the network-specific errors in `http/exceptions/`), which composes `default_message` + `"detail: <message>"` and pickles/copies through `__reduce__` (rebuilt from `args` + `__dict__`, never re-running `__init__`).
  - `APIStatusError.provider` is a `Provider` (`Provider.GENERIC` by default), as on the resolver.
  - The root module also holds `RequestValidationError(AIAPIError, ValueError)` (`provider`, `field` = the shared request field): an adapter raises it, before sending, for a shared request the provider cannot take (built with `request_errors(provider, fields)` and `check_last_turn` from `adapters/validation.py`, which wrap a provider method's pydantic `ValidationError` as `__cause__`; `field` is the shared name of the first failing field and the message lists every error under its shared name); errors of the shared request itself stay pydantic `ValidationError`s.
  - `http/exceptions/` splits network errors by what came back: HTTP errors (`status.py`) are `APIStatusError` subclasses keyed by status in `HTTP_ERRORS` (`raw` holds the parsed object that reported the failure, if any: OpenAI's failed `Response`, or a stream's error event that fits the item type); transport errors (`transport.py`, no response) are `APITransportError` subclasses (`APIRedirectError`, for a redirect that is not followed, `APIRequestError` and `APIStreamInterruptedError`, an open stream that broke or ended before its terminal, with `items_received`, are non-transient); `APIResponseError` (`response.py`, a response that is not valid HTTP, too large, cannot be decoded or validated, or breaks its protocol, such as an item after the terminal) has no `transient` flag and is never retried.
  - The first two carry a `transient` flag, which is the sole retry criterion (`session/retry.py`); waits use random exponential jitter but honor `retry_after`.
- **Error resolver (`http/exceptions/resolver.py`)** — `BaseErrorResolver.resolve()` extracts `{"error": {code,type,message}}` (a string `error` becomes the message), request-id headers, and `Retry-After` (through `get_header`/`parse_retry_after` in `http/headers.py`, RFC 9110 only: ASCII digits or an HTTP date, anything else is no header), then `classify()` picks the error class and transience (`TRANSIENT_STATUSES`, standard statuses only: a provider's own, such as Anthropic's 529, is its resolver's; 429 is transient only with `Retry-After`).
  - A provider subclass sets `provider` and `error_statuses` (the `ClassVar` table of the status each in-band code, else type, stands for) and overrides `get_error_code` and `classify_status`; `classify` keeps the in-band rule for every resolver: a status below 400 is looked up in the table and the result is never transient.
  - `HTTP_ERRORS` maps 413 to `ContentTooLargeError` (RFC 9110).
  - Each provider package has one `PROVIDER: Final` in its `api.py`, which its client, resolver and adapter set as `provider`.
- **API (`http/api.py`)** — `BaseAPI` validates `base_url` (absolute HTTP(S), no credentials, which aiohttp would send as Basic auth next to the session's own, no query/fragment) and `version` (one segment of unreserved characters, not `.`/`..`), because both are joined with `encoded=True`.
- **Clients (`client/`)** — `BaseClient[SessionT: ISession]` (`client/base.py`, protocol `IClient` in `client/protocols.py`) wraps a session, keeps its type in `session: SessionT`, delegates `send_request`/`stream`, and owns it: `close()` and `async with` close the session, also one passed in (by design, documented in README).
  - `BaseProviderClient` (`client/base.py`) is what provider clients share: `ClassVar`s `provider`, `session_factory` (an `ISessionFactory`, whose `error_resolver` property the check reads), `api_key_env`, `auth_headers` and `adapter_types` (every adapter class the client builds, one per shared resource; may be empty); `__init_subclass__` requires them and calls `check_same_provider(client=..., error_resolver=..., **providers_of(adapter_types, "adapter"))` (`client/validators.py`; `providers_of` keys each class as `"adapter <name>"` and raises `TypeError` for two classes of one name, which would drop one from the check), a `TypeError` listing every source on a mismatch; `adapter[**P, A](adapter_type: Callable[P, A], /, *args, **kwargs) -> A` builds an adapter, typed as a call of the class itself, and raises `TypeError` for a class not in `adapter_types` (exact membership: a subclass may name another provider; the test is kept apart from the `if`, since mypy narrows on `in`), so what is built is always what was checked; it reads only the class, so it may run before `super().__init__()`; `__init__(token, *, session, **session_kwargs: Any)` resolves the token, builds the session or checks the given one with the classmethod `warn_about_session` (a `SessionMismatchWarning`, a `UserWarning` from `ai_api/exceptions.py`, for an error resolver that is not an instance of the factory's resolver class, a subclass being fine, or an auth header outside `auth_headers`; turned off with the standard warning filters, not a setting; warnings use `skip_file_prefixes` of the package directory, so they point at the caller's code; `base_url` is not checked on purpose: gateways, proxies and Azure serve the API elsewhere), and the subclass types `session_kwargs` and builds its resources from `self.adapter(...)` after `super().__init__()` (the client layer cannot import `adapters` or `resources`, so it neither builds nor types them).
  - A user-given session is not checked against the provider.
  - `BaseClient.__aexit__` delegates to `session.__aexit__`.
  - `session/factory.py` holds `SessionFactory[SessionT, AuthT, **P]` (with its protocol `ISessionFactory` in `session/protocols.py`, both exported from `ai_api.session`) (session class + `auth_factory` + the provider's `IAPI` and error resolver; `factory(token_or_auth, **session_kwargs)`, where the `ParamSpec` makes type checkers check the remaining session arguments) and `resolve_token(token, session, env)` (`client/validators.py`): exactly one of token and session, and only when neither is given the token comes from the environment variable (empty counts as unset), so an explicit token always wins and a session is never combined with an env token.
  - Tests clear `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` with the autouse `no_provider_keys` fixture.
- **OpenAI (`providers/openai/`)** — `providers/openai/` has `OPENAI_API`, `OpenAIErrorResolver` (a 429 whose code or type is in `QUOTA_CODES` → non-transient `QuotaExceededError`; the flat stream `error` event `{"type": "error", "code", "message"}` is read as an `error` object, a status below 400 is classified by the status `ERROR_STATUSES` gives its code or type (the `QUOTA_CODES` stand for 429, so a quota in a stream is a `QuotaExceededError` too) and is never transient (the generation ran; the SDK retries by HTTP status only), and a failed `Response` or a `response.failed` event is resolved from `response.error`; an unmapped code such as `invalid_prompt` gives a plain non-transient `APIStatusError`), the module-level `session_factory`, `OPENAI_API_KEY_ENV` and `OpenAIClient(token | session=... | OPENAI_API_KEY, **session_kwargs)` (a `BaseProviderClient[OpenAIGenerationAdapter]`; `session_kwargs` are typed by `AiohttpSessionOptions`, a `TypedDict` in `session/aiohttp.py` of `AiohttpSession`'s keyword-only arguments, kept in step by a test, and passed to `session_factory`; given with `session=` they raise `ValueError`; with `generation: GenerationResource[Response, ResponseStreamEvent]` built on its session); a given session is checked by `warn_about_session`, which warns about a generic `BaseErrorResolver` or an auth header outside `auth_headers`.
  - `providers/openai/methods/` has `CreateResponse`/`StreamResponse` (`POST /responses`; `__retryable__ = True`, as in the SDKs, like Anthropic's methods; both mix in `ResponseParams` from `methods/base.py`, a plain `BaseModel` that holds only fields, so the method base's config wins; `Metadata` checks OpenAI's 16 pairs / 64 / 512 limits; `CreateResponse` has `BufferedResponseParser(error_responses=FAILED_RESPONSE)` (`FieldValues("status", "failed")` in `resolver.py`, the one test of a failed response, which the resolver uses too), so a `status: "failed"` response raises, stricter than the SDK; `StreamResponse` has `__stream_terminal__ = TERMINAL_EVENTS` (`response.completed`/`incomplete`/`failed`) and `error_events` that add `response.failed`) and `providers/openai/types/` the `Response` model (`output_text` is a computed property: the REST API has no such field) and the `ResponseStreamEvent` union; `providers/openai/adapters/` has `OpenAIGenerationAdapter` (`generation.py`, a `BaseCompositeAdapter` for `GenerationResource`) and its conversions (`conversions.py`: `InputConversion`, `UsageConversion` of `ResponseUsage`, `StopConversion` of a `Response`, also the one inside a stream's terminal event; the adapter takes them as `input_conversion`/`usage_conversion`/`stop_conversion` keyword arguments, defaults `INPUT_CONVERSION`/`USAGE_CONVERSION`/`STOP_CONVERSION`): only `completed`/`incomplete` buffered responses convert (`check_status`), any other status raises `APIResponseError`; a `refusal` content part gives `IncompleteReason.REFUSAL` and the joined `refusal` text, else `incomplete` gives `MAX_TOKENS` for `max_output_tokens` and `OTHER` otherwise (`INCOMPLETE_REASONS`), with `incomplete_details.reason` as `raw_incomplete_reason`; turns are sent as `{role, content}` items; method `ValidationError`s become `RequestValidationError`; the adapter leaves the end of a stream to the method's terminal and the use case.
- **Anthropic (`providers/anthropic/`)** — `providers/anthropic/` mirrors the OpenAI package: `ANTHROPIC_API`, `API_VERSION` (`2026-10-21`, the `anthropic-version` its types follow), `AnthropicErrorResolver` (`error.type` → `error_type`, `details.error_code` → `code`; 429 `enforced_spend_limit_reached` and a 400 whose message starts with `You have reached your specified` → non-transient `QuotaExceededError`; 529 → transient `ServiceUnavailableError`; a status below 400, i.e. a stream `error` event, is classified by the status `ERROR_STATUSES` gives its type and, as for OpenAI, is never transient), `session_factory` (`BearerAuth`), `ANTHROPIC_API_KEY_ENV` and `AnthropicClient` (with the same `**session_kwargs`), whose `auth_headers` are `Authorization` and `x-api-key`; it builds its adapter before calling `super().__init__()`, so a bad `default_max_tokens` fails before a session exists.
  - Its `methods/` has `CreateMessage`/`StreamMessage` (`POST /messages`, mixing in `MessageParams`; `MessageParam` and `Metadata` are `TypedDict`s with `extra="forbid"`, so dict literals type-check and unknown keys still fail; no `temperature`/`top_p`/`top_k`) and `__retryable__ = True` and `__request_headers__ = VERSION_HEADERS` (`anthropic-version: API_VERSION`): the version is set by the methods, not the session, because it fixes their wire format.
  - Its `adapters/` has `AnthropicGenerationAdapter(default_max_tokens=1024)` (`AnthropicClient(default_max_tokens=...)` builds `generation: GenerationResource[Message, MessageStreamEvent]`, checked before the session is built): `input` → one `user` turn, `instructions` → `system`, turns → `messages` as they are, metadata keys other than `user_id` → `RequestValidationError` (method fields are reported by their shared name, `SHARED_FIELDS`); `conversions.py` has the same three conversions, swapped the same way: `InputConversion` (a text → one `user` turn), `UsageConversion` of `Usage` (sums cached input into `input_tokens`, and reports the cache and thinking counts), `StopConversion` of a `Message` or a `MessageDelta`, which maps a `stop_reason` outside `FINISHED` (`end_turn`, `stop_sequence`) to a `Stop` (`incomplete_reason` via `INCOMPLETE_REASONS`, `MAX_TOKENS`/`REFUSAL`/`OTHER`, the `stop_reason` as `raw_incomplete_reason`, and for `refusal` `stop_details.explanation` else `category` as `refusal`), raises `APIResponseError` without a `stop_reason`; `StreamState` builds what a message has from the stream, so a stream goes through the same conversions: a real `Usage` (that of `message_start`, updated by the last cumulative `message_delta` counts; counts before `message_start` or a stream without it → `APIResponseError`) and a `MessageDelta` of the stop reason and details, used for the `CompletedEvent` on `message_stop` (`StreamMessage.__stream_terminal__` is `EventTypes("message_stop")`).
  - Its `types/` has `Message` (`text` is a computed property), `ContentBlock`/`ContentDelta` and the `MessageStreamEvent` union (`message_delta.usage` is cumulative and optional).
- **Provider unions and shared enums** — Provider unions never reject or drop an unknown `type`: `by_type(tags)` (`ai_api/types/unknown.py`, shared by the providers) is a callable pydantic discriminator that tags an unknown `type` as `UNKNOWN`, which maps to a `BaseUnknown` subclass (`extra="allow"`, so every field is kept); a value without `type` fails validation.
  - `response.failed`/`response.incomplete` are regular `ResponseStateEvent`s in the types (the parser raises `response.failed`); the Responses stream sends no `[DONE]`.
  - `Provider`, the method format enums (`BodyFormat`, `ResponseFormat`) and the shared generation values (`Role`, `IncompleteReason`, `GenerationEventType`, re-exported from the root) live in `ai_api/enums.py`, below every layer, so `types` and `client` never import `providers`, and parsers and body builders import `methods` only under `TYPE_CHECKING`.
- **Adapters (`adapters/`)** — every concrete adapter sets `provider: ClassVar[Provider]` (`_ProviderAdapter` in `adapters/base.py` raises `TypeError` in `__init_subclass__` otherwise; an abstract one may leave it out; the protocols expose it as a read-only property, which pyright accepts only from a subclass that assigns it), and the shared results and `RequestValidationError`s take it from there.
  - Pure model converters between shared types and a provider's methods, grouped by mode (not direction) so one class ties the method's result type to its conversion: `IAdapter`/`BaseAdapter[ReqT, RawT, RespT]` (`to_method(request) -> IAPIMethod[RawT]`, `to_response(raw, request)`), `IStreamAdapter`/`BaseStreamAdapter[ReqT, RawItemT, EventT]` (`to_stream_method(request)`, `to_events(items: AsyncIterator, request) -> AsyncIterator`, sees the whole stream so it may keep state, drop or split items) and the composites.
  - Adapters hold no session and do no I/O; the request is passed to the conversions for what the provider does not echo back.
  - A pure value conversion (the input, the token counts, the stop) is an `IConversion[SourceT, TargetT]` (`adapters/protocols.py`, `__call__(source, /)`, so a plain function fits) or a `BaseConversion` subclass (`adapters/base.py`); provider adapters take theirs as keyword arguments with defaults, so a caller swaps one without subclassing the adapter, and buffered and streamed results go through the same one.
  - A stop conversion returns `Stop` (`adapters/stop.py`: `incomplete_reason`, `raw_incomplete_reason`, `refusal`).
  - `to_response`/`to_events` stay in the adapter.
  - `tests/docs/test_unification.py` checks that every field of `docs/unification.md` is filled by a conversion every adapter has, or is listed as taken as is.
- **Resources and use cases (`resources/`) + shared types (`types/requests/`, `types/responses/`)** — the provider-neutral layer, wired into `OpenAIClient.generation` and `AnthropicClient.generation`.
  - `GenerationResource[RawT, RawItemT, SessionT = ISession](session, adapter)` (`resources/generation.py`, protocol `IGenerationResource`) is the one shared generation resource for every provider: it wraps an `AdapterCompositeUseCase` and offers `create(request)` / `stream(request)`; a provider client builds it with its own adapter.
  - Use cases only orchestrate: `AdapterUseCase`/`AdapterStreamUseCase`/`AdapterCompositeUseCase(session, adapter)` (`resources/usecases.py`, shared helpers `_respond`/`open_adapted_stream`/`_terminated`; the stream ones take keyword-only `terminal=`, an `IEventMatcher`, and then require exactly one matching event as the last one: none → `APIStreamInterruptedError`, or `RuntimeError` naming the adapter when the source method declares `__stream_terminal__` (its parser proved the source complete, so the adapter lost the event), an event after it → `APIResponseError`; `GenerationResource` passes `GENERATION_TERMINAL`, which matches `CompletedEvent`; its `create`/`stream` are `@overload`ed: the fields of `GenerationRequest` as keyword-only arguments (self is positional-only), or a positional `GenerationRequest`, both → `TypeError`, built by `_request`; `tests/providers/test_generation_api.py` checks that the keyword overloads name exactly the request fields; `stream` opens the adapter's stream through `open_adapted_stream` (`resources/usecases.py`, which the stream use cases use too) with `stream_type=GenerationStream`, so `transform_stream` builds the `GenerationStream` (`resources/stream.py`) on the converted events directly, with no second `Stream` around it; a `Stream` subclass that keeps the `CompletedEvent` it sees in `__anext__` and the error a read raised (raised again by every later read, `text()` and `final()`), with `text()` (text deltas) and `final()` (reads to the end and returns it; without one → `APIStreamInterruptedError`)) send `adapter.to_method(request)` and return `adapter.to_response(raw, request)`, or open `transform_stream(session.stream(adapter.to_stream_method(request)), lambda items: adapter.to_events(items, request))`; calls that are not one request and one response (pagination, several requests, polling) subclass the abstract bases by hand.
  - A use case turns a shared request (`BaseRequest`, `extra="forbid"`; `GenerationRequest`: `model`, `input` (a text or a non-empty list of `Turn`s, frozen `role: Role` + `content`; adapters require a last `user` turn), `instructions`, `max_output_tokens`, `metadata`; no sampling parameters, since Anthropic API `2026-10-21` removed `temperature`/`top_p`/`top_k`) into a provider method and the provider's result into a shared response (`BaseResponse`; `GenerationResponse[RawT]` with `incomplete_reason` (`IncompleteReason`: only `MAX_TOKENS`/`REFUSAL`/`OTHER`, values every provider has), `raw_incomplete_reason` (the provider's string), `refusal` (a refusal is an answer, as in the SDKs, never an error), `usage` (`TokenUsage` with `cache_read_tokens`/`cache_write_tokens`/`reasoning_tokens` as parts of input/output) and `to_turn()`, whose `RawT` is deliberately unbounded: a `BaseAPIType` bound plus `extra="ignore"` would turn an unparametrized `raw` dict into an empty model) or shared events (`GenerationEvent[RawT]`, a discriminated `type` alias of `TextDeltaEvent`/`CompletedEvent`/`OtherEvent`, whose `type` is `Literal[GenerationEventType.X]`; `CompletedEvent` carries the same stop fields as the response, plus `id`, `provider`, a required `model` and the whole `text` (Anthropic's `StreamState` keeps the `message_start` `Message`, its `usage` updated by `message_delta`, and the text deltas); a failure is an exception at every level, never an event).
  - `BaseUseCase`/`BaseStreamUseCase`/`BaseCompositeUseCase[ReqT, RespT(, EventT), SessionT = ISession]` and `BaseResource[SessionT = ISession]` all derive from `BaseSessionAccess[SessionT]` (PEP 696 default, so the session type is optional); protocols `ISessionAccess`/`IResource` and `IUseCase`/`IStreamUseCase`/`ICompositeUseCase`; `IGenerationClient[RawT = Any, RawItemT = Any]` (`resources/protocols.py`, since it names a resource protocol and `client` is a lower layer; per-resource client protocols of later resources go there too) is `IClient` plus a read-only `generation: IGenerationResource`, and every provider client matches it structurally.
  - A hand-written stream use case returns `transform_stream(source, transform)` (`response/stream.py`; `transform` gets the whole `AsyncIterator`) or its one-to-one case `map_stream(source, convert)`: it opens the source, yields a `Stream` of transformed items and on exit closes the transformed stream first and the source after it; a hand-written wrapper leaves its generator suspended until the event loop ends.
- **Protocols** — Most components have an `I*` `Protocol` in a sibling `protocols.py` (`IAPI`, `IAuth`, `IHeaders`, `IErrorResolver`, `IClient`, `ISessionFactory`, `ISessionAccess`/`IResource`, `IUseCase`/`IStreamUseCase`/`ICompositeUseCase`, `IAdapter`/`IStreamAdapter`/`ICompositeAdapter`, `IAPIMethod`/`IStreamMethod`, `IResponseParser`/`IStreamParser`, `IStreamResponse`, `IBodyBuilder`, `ISession`).
  - Sessions depend on protocols, not concrete classes; the user supplies an `IAPI` (base_url/version/`build_url`) per provider.

## Conventions

- Industry standards and the official provider SDKs' behaviour take precedence over local rules, but only where that is logically justified for the library: "the SDK does it" alone is no argument, either way. A conflict is settled with the maintainer.
- A shared (unified) type holds what every provider has; provider-only data stays in the provider's own types and is reached through `raw`.
- Packages are layers and sit directly under `ai_api/`, in dependency order: core (`__meta__.py`, `enums.py`, `exceptions.py`) → data (`types/`, `serialization/`) and HTTP primitives (`http/`: API, auth, headers, and `http/exceptions/`) → `methods/` → `response/` → `session/` → `client/` → `adapters/` → `resources/` → `providers/<name>/`. A module imports only from the layers below it; the only exception is `methods/base.py`, which imports the default parsers from `response/parse/`, and protocols that refer to each other import under `TYPE_CHECKING`. No package holds a single module, nothing is nested more than three levels below `ai_api/`, and a module is named after its content, never after its package; these layout rules apply where they do not break a package's meaning (a rule that would split or misname what belongs together is reconsidered with the maintainer) (`base.py` holds base classes, `protocols.py` the protocols; `response/X.py` is a kind of response and `response/parse/X.py` its parser).
- Transport-specific code lives only in `<layer>/<transport>.py` modules (today `http/exceptions/aiohttp.py`, `response/aiohttp.py`, `session/aiohttp.py`, `session/body/aiohttp.py`) and is never imported from an `__init__.py`, so the core imports without the transport and a second transport (e.g. httpx) adds `*/httpx.py` files. The only exception is a provider package's `__init__.py`, which re-exports its client and so binds its transport.
- Public imports: every package `__init__.py` re-exports its layer's public names with a sorted `__all__` (`tests/unit/test_public_api.py` checks them, and that `import ai_api` does not load aiohttp), and `ai_api/__init__.py` re-exports what most code needs: method and type base classes, files, enums, auth, `BaseAPI`, `Headers`, `Stream`, `ServerSentEvent`, `BaseSession`, `BaseClient`, `BaseProviderClient`, `BaseErrorResolver`, the whole error tree, `SessionMismatchWarning` and the shared generation layer (`GenerationRequest`, `Turn`, `GenerationResponse`, `TokenUsage`, the events, `GenerationStream`, `IGenerationResource`, `IGenerationClient`). Internal helpers (`methods/fields.py`, `methods/path.py`, `client/validators.py`, `adapters/validation.py`, decoders, constants) are not re-exported.
- Naming: a method property is its dunder without underscores (`__request_body_format__` → `request_body_format`), except `__returning__` → `response_type`, kept from the aiogram-style design; stream generics are `ItemT`, buffered ones `ResponseT`; a response argument is named `response`, never `buffered`; module-level constants are `Final` and upper case (callables such as `session_factory` stay lower case); a helper with no callers outside its module starts with `_`; header names and media types are constants in `http/headers.py`; enums are compared with `is`; constructor arguments after the required collaborators are keyword-only.
- A provider is a flat package: `providers/<name>/api.py` (its `IAPI`), `resolver.py` (its error resolver) and `client.py` (client and session factory); `types/`, `methods/` and `adapters/` subpackages come with its first endpoints, and its resources build `AdapterUseCase`s from those adapters.
- Every module, class, function and method (including private ones and protocol members) has a Google-style docstring (`Args:`, `Returns:`, `Yields:`, `Raises:`, `Attributes:`, `Example:`). Ruff enforces this (`D` rules, `convention = "google"` in `pyproject.toml`), so `uv run ruff check src` fails on missing or malformed docstrings.
- Uses modern syntax that Python 3.13 supports: PEP 695 generics (`class Foo[T]`, `def parse[T]`, `type X = ...`) and PEP 696 defaults (`[SessionT: ISession = ISession]`). Every module starts with `from __future__ import annotations` (ruff's `required-imports` adds it), so names imported under `TYPE_CHECKING` and forward references are used unquoted in annotations; 3.13 has no deferred evaluation of its own (PEP 649 is 3.14). Do not use 3.14+ syntax or stdlib APIs, such as `except A, B:` without parentheses (PEP 758).
- A provider type uses `Literal` for a schema constant that names the object (`type`, `object`, `role: "assistant"`) and `str` for an enumeration that grows (`status`, `stop_reason`, error codes), so a new value of the latter does not fail a whole response.
- `Provider` is a closed enum, extended only inside the library together with a provider package (its `PROVIDER` constant); an adapter or client outside the library uses `Provider.GENERIC`.
- Ruff rule set is broad (pylint, bugbear, simplify, etc.); `print` is disallowed (T20) and naive datetimes are flagged (DTZ).
