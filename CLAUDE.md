# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`aiollm` is a pre-alpha (0.6.0), async-first, low-level toolkit for building typed HTTP API clients, aimed at AI providers. It ships the infrastructure, `OpenAIClient` (OpenAI's Responses API) and `AnthropicClient` (Anthropic's Messages API), both with the provider-neutral `client.generation`. The public surface is unstable.

**The code says what the library does; an agreed decision says what it should do.** This file, the README and the site describe the code and may lag. When they disagree, find the cause: a text that lags behind the code is fixed; code that contradicts an agreed decision is a bug, raised with the maintainer, never settled by declaring the code right. `CONTRIBUTING.md` (also the site's Contributing page) is the guide for contributors, with directives for those who work with Claude; keep it in step with this file. The user documentation is the MkDocs site in `docs/` (published at <https://grehban.github.io/ai_api/>); its reference pages are generated from the docstrings, so a docstring is user documentation too.

## Commands

The project is managed with `uv` (see `uv.lock`) and requires Python 3.13 or newer (`.python-version` pins 3.13, the oldest supported version, so local runs and CI catch newer syntax). The version is read by hatchling from `src/aiollm/__meta__.py`.

```bash
uv sync --all-groups                 # install runtime + dev + test + docs deps
uv run ruff check src tests          # lint (line length 79)
uv run ruff format src tests         # format
uv run mypy src                      # strict type checking (pydantic.mypy plugin)
uv run pyright                       # strict pyright over src and tests
uv run pytest                        # tests (testpaths = tests, asyncio_mode = auto)
uv run pytest tests/path/test_x.py::test_name   # single test
uv run pytest --cov                  # with coverage (branch, fail_under = 98)
uv run pytest --mypy -m mypy tests/typing       # static checks of the public API
uv run mkdocs serve                  # the docs site at http://127.0.0.1:8000
uv run mkdocs build --strict         # build it; any warning fails
uv run rumdl check README.md CHANGELOG.md CONTRIBUTING.md docs   # Markdown lint
uv run pre-commit install            # once: hooks from .pre-commit-config.yaml
uv run towncrier create +slug.fixed.md   # a changelog fragment in CHANGES/
uv run towncrier build --draft       # preview the next CHANGELOG section
```

CI (`.github/workflows/tests.yml`) runs the checks, the Markdown lint and `mkdocs build --strict` (job `lint and types`), pytest on Ubuntu and Windows × every supported CPython (3.13, 3.14, 3.15; the `tests` job sums up the matrix, so the branch ruleset needs one stable name), a wheel built and imported in a clean environment (`package`), `uv audit` of the lockfile (`audit`) and, on pull requests, `towncrier check` (`changelog`: a PR adds a fragment to `CHANGES/` or changes `CHANGELOG.md`; the `no changelog` label skips it); `.github/workflows/docs.yml` publishes the site to GitHub Pages on every push to `master`. Set `NO_MKDOCS_2_WARNING=1` to hide Material's notice about its end of life.

## Tests

- `tests/unit/`, `tests/session/` (`BaseSession` and `SessionFactory` on a fake transport), `tests/integration/` (aiohttp against the local server; `test_close_delimited.py` and `test_upload_attempts.py` use raw socket servers to cut bodies and break upload attempts), `tests/providers/`, `tests/typing/`, `tests/docs/`.
- `tests/conftest.py` holds the shared doubles and fixtures. `Recorder` (the local server) answers only what a test scripted with `recorder.reply(...)` or an explicit `recorder.default`; any other request gets a 500 and fails the test at teardown, so a hidden retry or an extra request cannot pass. `no_close_delay` patches only `session.aiohttp._CLOSE_DELAY`, `frozen_now` only `http.headers._now` (the library's one wall-clock read; the transport also times attempts with `time.perf_counter` for its log), the autouse `no_retry_wait` only `session.retry.runner.calculate_wait` (waits 0 s and skips the policy's `backoff`; a test that needs the real wait sets its `side_effect` to `calculate_wait` imported before the patch), and the autouse `no_provider_keys` clears `OPENAI_API_KEY` and `ANTHROPIC_API_KEY`.
- `tests/providers/test_generation_contract.py` runs the same scenarios against every provider's `client.generation` and `test_provider_clients.py` against every client, so a new provider adds a `Case` and a `ClientCase`; `test_<name>_client.py` keeps what is the provider's own.
- `tests/providers/test_wire_contracts.py` checks every provider endpoint against the upstream JSON schemas and examples snapshotted in `tests/providers/contracts/` (request schemas closed, so unknown fields fail). A new endpoint adds an `Endpoint` to `contracts/update.py` and a `Case`; `uv run python -m tests.providers.contracts.update [DOCS_LITE_DIR]` refreshes the snapshot. Every provider model except the `BaseUnknown` ones sets `__upstream_schema__`, the upstream `$def` it mirrors, and each field is checked against it.
- `tests/typing/check_public_api.py` is never run: every `# type: ignore[...]` there marks a line that must stay a type error.
- `tests/docs/test_examples.py` runs every ```` ```python ```` block of `README.md` and `docs/**/*.md` (except the historical `testing-plan.md` and `sse-ndjson-plan.md`). Blocks are found by `title="name.py"` on the fence line; a block without a title, a duplicate title or a title no test runs fails `test_every_example_is_tested`, so a new example needs a title and a test. `tests/docs/test_unification.py` checks that `docs/unification.md` has a row for every field of the shared types and that every error case raises what it names.
- Coverage is kept at 100 % in practice (the configured floor is 98).

Offline provider documentation (OpenAI, Anthropic, OpenRouter, Gemini: endpoints, JSON schemas, stream contracts, fixtures; its `docs-lite` folder is also the source of the contract snapshot) comes from the `unified-api-docs` MCP server in `.mcp.json`, enabled in `.claude/settings.json`. It runs `docs-suite-mcp` from the private repository `GrehBan/docs-lite-mcp`, expected at `/home/user/docs-lite-mcp` (cloud sessions); elsewhere set `DOCS_SUITE_MCP_DIR` to its `docs-suite-mcp` folder. `.mcp.json` is never committed.

## Skills

The project's workflows are skills in `.claude/skills/`: `ai-api-release` (a changelog fragment in every change; a release as its own PR that builds the CHANGELOG with towncrier and bumps the version; commit and PR rules; tags are never created), `ai-api-endpoint` (a new endpoint or field of an existing provider, from the upstream schema to the wire contracts), `ai-api-provider` (a new provider package) and `ai-api-docs` (guide pages, docstrings and tested examples). ## Architecture

The guide pages (`docs/guide/`) describe the behaviour for users; read the code for the details. What follows are the invariants that are easy to break.

- **Request flow.** A `BaseAPIMethod` → `BaseSession.send_request` → (tenacity retry, only if `method.retryable`, by the call's `retry_policy` or else the session's `RetryPolicy`, 4 attempts by default) `_send_once` → transport `_execute` → `BufferedResponse` → `_raise_for_status` → `method.response_parser`. The status check stays inside the retried `_send_once`: the raised error's `transient` flag is the only thing that allows a retry; a policy's `retry_if` can only refuse one, and an error raised by `retry_if` or `backoff` (or an invalid wait) gets the request's error as its `__cause__`, since tenacity would drop it (`session/retry/runner.py`).
- **Stream flow.** `async with session.stream(method)` retries only the opening (`_open_stream_once` → transport `_open_stream` → `IStreamResponse`, ≥ 400 read and raised there), then yields `Stream(method.stream_parser.parse(...))` and closes parser and response on exit, both through `closing_source`, so a failing close (an upload left open) is a note on the error that ended the block, not a replacement. Failures while iterating reach the caller; `Stream` wraps transport errors in `APIStreamInterruptedError`. A declared `__stream_terminal__` makes the parser require it as the last item.
- **Methods** are Pydantic models configured by dunder `ClassVar`s (`__request_path__`, `__request_method__`, `__request_query__`, `__request_body_format__`, `__request_headers__`, `__value_formatter__`, `__retryable__`, `__returning__`, `__response_format__`, `__response_parser__`/`__stream_parser__`, `__stream_terminal__`). The protocols (`methods/protocols.py`) expose only regular properties, never the dunders: putting a dunder `ClassVar` into a protocol breaks pyright's protocol matching. Class-level checks (path template, query fields, body fields, response type vs format) run in `__pydantic_init_subclass__` and raise `TypeError` at class definition; they run on user-declared classes only (`__pydantic_generic_metadata__["origin"] is None`), and an explicit parser skips the format check. Wire names go in `validation_alias`/`serialization_alias`, never `alias`.
- **Optional fields.** A request field without a default is required, `None` is sent as `null`, and a field that defaults to `MISSING` (pydantic's sentinel) is left out of the body and the query. A default of `None` (also from a default factory, called once to see; `defaults_to_none`), or a class of data with one anywhere in a field's type (models, dataclasses, `NamedTuple`, behind `NewType` too; `nested_data_classes` and `none_defaults` in `methods/fields.py`), raises `TypeError` once the class is complete, and so does `MISSING` in a type without the `MISSING` default or the other way round (`names_missing`; `Any` takes it) (`_check_defaults` from `__pydantic_on_complete__`: at definition, or at the first use of a class that names a type defined further down; the message is kept in `__definition_error__` and `model_post_init` raises it for every instance, since Pydantic keeps such a class usable; `exclude=True` fields are skipped), so nested request data is a `TypedDict`. The walk remembers models, `TypedDict`s and type aliases, so a recursive alias (`type JSON = dict[str, JSON] | ...`) ends; `guard_traversal` is for values and would raise on a cycle, which is legal in a type. A type with a `PlainSerializer` (`serialized_by_hand`) is not looked into, since the serializer decides what is sent. `get_body_map` dumps without `exclude_none`, so a model put into a body at run time sends `None` as `null` too (a response item goes back as it came only through `model_dump(exclude_unset=True)`). Shared requests (`BaseRequest`) validate assignments; adapters still meet whatever `model_copy` lets past and leave it to the method's validation. The query and the form refuse `None` (`ValueError`); `MISSING` inside a list or a dict raises `ValueError` in the normalizer and the query; a path field cannot default to `MISSING`.
- **Paths.** `request_path` is already percent-encoded (that escaping prevents path injection), so `IAPI.build_url` joins it with `URL.joinpath(..., encoded=True)`; yarl's `/` would double-encode.
- **Sessions.** `BaseSession` holds all transport-neutral logic; a transport implements `_execute`, `_open_stream` and `close()`, returning error statuses as responses and raising `APITransportError` subclasses for I/O failures (mapped in one place, `http/exceptions/aiohttp.py`). `AiohttpSession._request` builds the headers on every request (session < method < call < auth, auth last) and never passes `timeout=None` to aiohttp, which would disable every limit. A session is bound to one event loop (`session/loop.py`), and the `loop` property never binds one.
- **Uploads.** Every attempt has an `AsyncExitStack` (`uploads`): the body builder opens each upload at once and registers its reader with `push_async_exit`, the session adds `wait_for_writer`; the order on exit is release the response, wait for the writer, close the readers (aiohttp neither closes a body iterator it stops writing nor waits for the task it cancels). `types/files.py` holds the lifecycle helpers: `closing_source` (one close rule, a failing close becomes a note on the error that ended the block), `ThreadWork` (blocking calls in a worker thread; a cancelled call runs on, and the resource is released or reused only after it: `finish` is async, runs a blocking cleanup in the thread, never in the loop, and puts it off into a kept task while a call runs; a failure nobody can receive any more is noted on `finish`'s `error` and reported through the loop's exception handler, never dropped and never raised into a later caller) and `open_file`; `_READERS` holds an `IOFile` lease per stream.
- **Errors.** `AIAPIError` (root `exceptions.py`) composes `default_message` + `detail: <message>` and pickles through `__reduce__`. `http/exceptions/` splits by what came back: `APIStatusError` (by status in `HTTP_ERRORS`, or in-band failures below 400, which are never transient), `APITransportError` (no response) and `APIResponseError` (unusable response, never retried). Resolvers (`BaseErrorResolver` and the providers') return errors; `classify` keeps the in-band rule for every resolver.
- **Clients and providers.** `BaseClient` owns its session (also a given one). `BaseProviderClient.__init_subclass__` checks that client, resolver and adapters name one `Provider`. A provider client declares each shared resource as a class attribute made by `bind_resource` (`client/binding.py`): it returns a `ResourceBinding` typed as the resource, like `dataclasses.field`, because pyright does not apply a descriptor's `__get__` when it matches a class against a protocol's property (`IGenerationClient.generation`). `BaseProviderClient.__init__` builds every adapter before the session and every resource after it. A provider package has one `PROVIDER: Final` in its `api.py`.
- **Shared layer.** Adapters (`adapters/`) are pure converters with no session or I/O; use cases (`resources/usecases.py`) only orchestrate and pass the call's `CallOptions` (`headers`, `timeout`, `retry_policy`, the keyword-only arguments of `ISession.send_request`, kept in step by a test) to the session unchanged; `client.generation` takes them next to the request fields, so no `GenerationRequest` field may be named like one (a test checks); `GenerationResource` is the one generation resource for every provider and checks that a stream ends with exactly one `CompletedEvent`. `docs/unification.md` lists what every shared field becomes per provider.

## Conventions

- Industry standards and the official provider SDKs' behaviour take precedence over local rules, but only where that is logically justified for the library: "the SDK does it" alone is no argument, either way. A conflict is settled with the maintainer.
- A change PR adds a fragment to `CHANGES/` and never bumps the version or edits `CHANGELOG.md`; a release is a separate PR that runs `towncrier build` and bumps `__meta__.py`, the README and this file (`ai-api-release`), so parallel PRs never conflict in the changelog.
- A shared (unified) type holds what every provider has; provider-only data stays in the provider's own types and is reached through `raw`.
- Request fields follow the upstream schema: `None` in the type only where it allows `null`, a `MISSING` default only where the field is optional, no default where it is required (`test_method_fields_match_the_request_schema` checks the provider methods). Shared requests take no `None` (`T | MISSING = MISSING`) and adapters pass the values on unchanged; response types keep `= None`, since they are never sent as requests.
- Packages are layers and sit directly under `aiollm/`, in dependency order: core (`__meta__.py`, `enums.py`, `exceptions.py`) → data (`types/`, `serialization/`) and HTTP primitives (`http/`: API, auth, headers, and `http/exceptions/`) → `methods/` → `response/` → `session/` → `client/` → `adapters/` → `resources/` → `providers/<name>/`. A module imports only from the layers below it; the only exception is `methods/base.py`, which imports the default parsers from `response/parse/`, and protocols that refer to each other import under `TYPE_CHECKING`. No package holds a single module, nothing is nested more than three levels below `aiollm/`, and a module is named after its content, never after its package; these layout rules apply where they do not break a package's meaning (a rule that would split or misname what belongs together is reconsidered with the maintainer) (`base.py` holds base classes, `protocols.py` the protocols; `response/X.py` is a kind of response and `response/parse/X.py` its parser).
- Transport-specific code lives only in `<layer>/<transport>.py` modules (today `http/exceptions/aiohttp.py`, `response/aiohttp.py`, `session/aiohttp.py`, `session/body/aiohttp.py`) and is never imported from an `__init__.py`, so the core imports without the transport and a second transport (e.g. httpx) adds `*/httpx.py` files. The only exception is a provider package's `__init__.py`, which re-exports its client and so binds its transport.
- Public imports: every package `__init__.py` re-exports its layer's public names with a sorted `__all__` (`tests/unit/test_public_api.py` checks them, and that `import aiollm` does not load aiohttp), and `aiollm/__init__.py` re-exports what most code needs: method and type base classes, files, enums, auth, `BaseAPI`, `Headers`, `Stream`, `ServerSentEvent`, `BaseSession`, `BaseClient`, `BaseProviderClient`, `bind_resource`, `BaseErrorResolver`, the whole error tree, `SessionMismatchWarning`, the retry policy (`RetryPolicy`, `RetryState`, `FullJitterBackoff`) and the shared generation layer (`GenerationRequest`, `Turn`, `GenerationResponse`, `TokenUsage`, the events, `GenerationStream`, `IGenerationResource`, `IGenerationClient`). Internal helpers (`methods/fields.py`, `methods/path.py`, `client/validators.py`, `adapters/validation.py`, decoders, constants) are not re-exported.
- Naming: a method property is its dunder without underscores (`__request_body_format__` → `request_body_format`), except `__returning__` → `response_type`, kept from the aiogram-style design; stream generics are `ItemT`, buffered ones `ResponseT`; a response argument is named `response`, never `buffered`; module-level constants are `Final` and upper case (callables such as `session_factory` stay lower case); a helper with no callers outside its module starts with `_`; header names and media types are constants in `http/headers.py`; enums are compared with `is`; constructor arguments after the required collaborators are keyword-only.
- A provider is a flat package: `providers/<name>/api.py` (its `IAPI`), `resolver.py` (its error resolver) and `client.py` (client and session factory); `types/`, `methods/` and `adapters/` subpackages come with its first endpoints, and its resources build `AdapterUseCase`s from those adapters.
- Every module, class, function and method (including private ones and protocol members) has a Google-style docstring (`Args:`, `Returns:`, `Yields:`, `Raises:`, `Attributes:`, `Example:`). Ruff enforces this (`D` rules, `convention = "google"` in `pyproject.toml`), so `uv run ruff check src` fails on missing or malformed docstrings.
- Uses modern syntax that Python 3.13 supports: PEP 695 generics (`class Foo[T]`, `def parse[T]`, `type X = ...`) and PEP 696 defaults (`[SessionT: ISession = ISession]`). Every module starts with `from __future__ import annotations` (ruff's `required-imports` adds it), so names imported under `TYPE_CHECKING` and forward references are used unquoted in annotations; 3.13 has no deferred evaluation of its own (PEP 649 is 3.14). Do not use 3.14+ syntax or stdlib APIs, such as `except A, B:` without parentheses (PEP 758).
- A provider type uses `Literal` for a schema constant that names the object (`type`, `object`, `role: "assistant"`) and `str` for an enumeration that grows (`status`, `stop_reason`, error codes), so a new value of the latter does not fail a whole response.
- `Provider` is a closed enum, extended only inside the library together with a provider package (its `PROVIDER` constant); an adapter or client outside the library uses `Provider.GENERIC`.
- Ruff rule set is broad (pylint, bugbear, simplify, logging, etc.); `print` is disallowed (T20), naive datetimes are flagged (DTZ), and log calls take lazy `%` arguments, never f-strings (G).
- Logging: only a module that logs has `logger = logging.getLogger(__name__)` (add it with the first call); `aiollm/__init__.py` only adds a `NullHandler` to `aiollm`. An exception that reaches the caller is never logged (no `logger.error` before `raise`: 400/401/404, exhausted retries, parse errors, `CancelledError`, a close error added as a note). What the library handles or swallows is: a retry at WARNING (the failed attempt's error type and how many notes it has), a recovered or deliberately suppressed error at DEBUG (by its type, never its message, notes or traceback), details of a call at DEBUG; INFO only for a significant success. A failure no caller can receive goes through `ThreadWork`'s `_report` to the loop's exception handler only, never also `logger.exception`. Each layer logs only its own part: `session.base` a call's start, end and retries, the transport each attempt (sent, with the declared `request_path_template`; finished with status and duration). Never log, at any level, tokens, keys, headers, bodies, query strings, the values of path parameters, an error's message, notes or traceback, or file names (the official SDKs log bodies at DEBUG; we do not, prompts are personal data), and add no env var that configures logging. The records are listed in `docs/guide/sessions.md` and checked by `tests/integration/test_logging.py`.
