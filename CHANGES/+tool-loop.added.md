A conversation can carry a tool loop: `GenerationRequest.input` takes `ToolCallTurn`s (the model's calls, with its text) and `ToolResult`s (`call_id`, `output`) next to `Turn`s, as `InputItem`s. `GenerationResponse.to_turn()` gives a `ToolCallTurn` for a response with calls, holding the response's own output in `native` (`GenerationResponse.native`), so the provider gets its reasoning back (OpenAI's reasoning items, Anthropic's signed thinking); another provider gets the shared calls. Every adapter refuses a conversation out of order (a call without its result, a result without its call, text between them) before sending, and Anthropic's adapter calls whose arguments are not a JSON object.
