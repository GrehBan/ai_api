**Breaking:** OpenAI's and Anthropic's own types are now generated from their schemas (OpenAI's official OpenAPI file, Anthropic's documentation snapshot) and cover the whole of each endpoint: every output item, content block, tool and stream event the schema names, with request parameters in the new `aiollm.providers.openai.methods.params` and `aiollm.providers.anthropic.methods.params`. Names follow the schemas, so code that imports provider types migrates: OpenAI `OutputText` → `OutputTextContent`, `OutputRefusal` → `RefusalContent`, `OutputTextDeltaEvent` → `ResponseTextDeltaEvent`, `ResponseStateEvent` → `ResponseCompletedEvent`, `ResponseIncompleteEvent` and the others of its kind, `UnknownOutputItem`, `UnknownContent` and `UnknownEvent` → `UnknownVariant`; Anthropic `MessageStartEvent`, `ContentBlockDeltaEvent` and the other events → `RawMessageStartEvent`, `RawContentBlockDeltaEvent`, ..., `MessageDelta` → `Delta`, `StopDetails` → `RefusalStopDetails`, `UnknownBlock`, `UnknownDelta` and `UnknownEvent` → `UnknownVariant`, and a `ping` is an `UnknownVariant`; `MessageParam`, `ResponseParams`, `Reasoning`, `TextConfig` and the other request `TypedDict`s give way to the generated models, which take dicts at run time and refuse unknown keys. `Response.output_text`, `Response.reasoning_summary`, `Message.text` and `Message.thinking` are gone: OpenAI's `output_text` is a schema field the API leaves out, so use `output_text()` and `reasoning_summary()` from `aiollm.providers.openai.adapters` and `message_text()` and `message_thinking()` from `aiollm.providers.anthropic.adapters`. The types follow the schemas strictly: OpenAI's `usage` needs its `input_tokens_details` and `output_tokens_details` and an `output_text` part its `annotations` and `logprobs`, Anthropic's `message_delta` its `usage`, and an Anthropic turn may be a `system` one. The early checks the schemas do not state stay: OpenAI's `metadata` limits, and Anthropic's at least one turn, `max_tokens` from 0 and `metadata.user_id` up to 512 characters.
