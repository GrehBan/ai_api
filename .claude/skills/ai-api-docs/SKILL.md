# aiollm docs

The code is the source of truth about what the library does; the docs must
say exactly that. Every Python block on the site runs in a test, so an
example that drifts from the code fails CI instead of misleading a user.

## Where things go

- `README.md`: status line, short pitch, install, quick start; its intro is
  shared with `docs/index.md` through a snippet.
- `docs/guide/*.md`: how to use a feature (methods, uploads, streaming,
  errors, sessions, providers, generation, resources, extending, design).
- Reference pages: generated by mkdocstrings from docstrings - a Google-style
  docstring is user documentation; fix it there, not on a page.
- `docs/unification.md`: one row per shared field and error case
  (`tests/docs/test_unification.py` checks the rows and the errors).
- `CHANGELOG.md`: what a user sees, under `[Unreleased]`, breaking entries
  with migration steps.
- `CLAUDE.md`: invariants and conventions for agents only.
- Historical plans (`testing-plan.md`, `sse-ndjson-plan.md`) are not edited.

## Checking a statement

Before writing a sentence about behaviour, find the code that does it
(`file:line`) or run a probe. If the text and the code disagree, the code
wins - unless it looks like a bug, then tell the owner instead of documenting
the bug.

## Examples

- Every ```` ```python ```` block needs `title="name.py"` on the fence line,
  unique across README and `docs/`.
- `tests/docs/test_examples.py` runs blocks in one module, like a reader
  pasting them: add the title as a constant, put it in `TESTED`, and write a
  test that runs it (often after `QUICK_START`) and asserts what the example
  claims (the request sent, the body map, the result).
- Names the examples may use without defining them: `ModelList`, `Model`,
  `Transcription`, `data`, `chunks`, `session` (see the `examples` fixture).
- A block that is not meant to run is not a Python block: use `text`.

## Checks

```bash
uv run pytest tests/docs
uv run rumdl check README.md CHANGELOG.md docs
uv run mkdocs build --strict
```

The site is published from `master` by `.github/workflows/docs.yml`. Report
in Russian: pages changed, examples added and their tests, checks run.
